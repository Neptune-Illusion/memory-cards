# Obsidian 闪卡插件 — 记忆学习方案产品规格

版本：v0.2（可实施规格，含 §3.5 移动优先体验规范）
作者：OpenCode（Behavioral Nudge Engine + UX Architect 模式）
日期：2026-08-13
状态：Draft（供 Lead / 实现成员审阅）

---

## 0. 设计原则（why）

学习效果取决于四条认知定律，插件设计必须**直接服务于**它们：

| 定律 | 定义 | 插件如何服务 |
|---|---|---|
| **主动回忆**（Active Recall） | 从记忆中提取答案比重复阅读更能强化记忆 | 卡片默认隐藏答案；提问在前、揭晓在后；评分前必须"先想" |
| **间隔重复**（Spaced Repetition） | 在即将遗忘的时间点复习最有效 | 基于遗忘曲线调度复习，随掌握度拉长间隔 |
| **遗忘曲线**（Forgetting Curve） | 记忆按指数衰减，衰减率因人因卡而异 | 调度算法按每次评分动态调整间隔 |
| **低摩擦**（Low Friction） | 摩擦越大，坚持率越低 | 复习流程≤2次点击/卡；单手/键盘操作；断点续练 |

反面约束（**anti-goals**）：
- 不制造"熟悉感偏差"——即看答案眼熟而非真正回忆出来，就误点"认识"。见 §8 反作弊机制。
- 不做"刷量"——评分按钮若引导用户无脑点"认识"以获得进度，会毁掉数据与效果。
- 不堆功能——MVP 聚焦"用起来+用得对"，而非"功能全"。

## 1. 产品定义（MVP 边界）

### 1.1 一句话
一个 Obsidian 插件：把笔记变成可主动回忆的卡片，用间隔重复调度复习，让用户每天花最小力气获得最高记忆保持。

### 1.2 MVP 范围（必须）
- 从指定文件夹读取卡片（含子文件夹递归）。
- 手动创建卡片（Quick Add）。
- 复习会话：先看问题 → 主动回忆 → 点揭示 → 按真实回忆质量评分。
- 间隔重复调度器（SM-2 派生）。
- 持久化复习状态（DataView/data.json，不进笔记文件）。
- 基础统计（到期数、今日复习数、掌握率、连续打卡）。
- 反作弊 / 防熟悉感偏差（§8）。

### 1.3 明确排除（MVP 不做）
- 拖拽/图形调度、AI 生成卡片、音频卡、图片遮挡、命令面板深度集成、移动端进阶——留待 v0.2+。
- 同步逻辑（Obsidian Sync 原生处理 data.json 即可，不做自定义冲突合并）。

### 1.4 成功标准（可度量）
- **坚持率**：新用户首周 4+ 天复习 ≥ 60%。
- **掌握率**：卡片在 30 天内进入"长期间隔（≥3 周）"比例 ≥ 50%。
- **摩擦**：单卡平均评分耗时 < 8 秒。
- **数据质量**：反作弊触发后（评分异常一致）出现"诚实修正"的比例 ≥ 70%。

## 2. 卡片格式（数据模型）

### 2.1 笔记内标记（frontmatter + 分隔符）

`## 记忆卡`（或可配置分隔符 `???` 与 `:::`)：

```markdown
---
memtype: card
tags: [记忆卡, 生物]
---

问题：细胞呼吸的三阶段分别是什么？

??? 答案

答案：糖酵解、柠檬酸循环（Krebs）、氧化磷酸化。

::: 注解

注解：糖酵解在细胞质，后两者在线粒体。
```

解析规则：
- 问题 = 分隔符前的内容；答案 = 分隔符后内容。
- 支持 `::: 注解` 可选块——评分后展示，用于"我为什么错/怎么记"（增强编码）。
- frontmatter `tags` 用于按主题筛选复习。
- 一个 `.md` 文件可含多张卡（用多个分隔符），每张卡独立调度。

### 2.2 索引（卡片元数据）
卡片唯一 ID = `notePath::frontmatterId`（无 frontmatter 用 `notePath::分隔符序号`），确保笔记重命名/移动后仍稳定。

### 2.3 复习状态（data.json，非侵入式）
```json
{
  "cardId": {
    "state": {
      "reps": 4,          // 已复习次数
      "intervalDays": 21, // 当前间隔（天）
      "easeFactor": 2.5,  // 难度系数
      "dueAt": "2026-09-03T08:00:00.000Z",
      "lastGrade": 4,     // 上次评分 0-5
      "lapses": 0,        // 遗忘次数（评分<3）
      "createdAt": "...",
      "firstLearnedAt": null
    }
  }
}
```

## 3. 复习流程（UX 低摩擦）

```
复习会话启动
   ↓
[问题卡片 —— 全屏/居中]
   · 仅显示问题
   · 顶部：进度条（当前/总数）+ 退出按钮
   · 键盘快捷键：空格=揭晓
   ↓
[用户主动回忆（无时间限制，心理计时）]
   · 页面提示"在脑海里回答，再揭晓"（主动回忆钩子）
   · 若 <3 秒就揭晓 → 温和提示"要不要再想想？"（反作弊 §8）
   ↓
[点击 揭晓答案]
   ↓
[评分栏 —— 4 档按钮，横向，拇指可及]
   [忘记] [模糊] [正确] [轻松]
   · 单选即时生效 → 自动进入下一张（零额外点击）
   · 键盘：1/2/3/4
   ↓
循环 / 会话结束展示统计
```

- 单卡总点击 = 2（揭晓 + 评分）。可全键盘操作。
- 每 5 张卡插入一条"进度/鼓励"微激励（Behavioral Nudge：变量奖励）。

### 3.1 评分按钮语义（对齐 SM-2）
| 档位 | 值 | 含义 | 间隔影响 |
|---|---|---|---|
| 忘记 Again | 2 | 完全没想起 | 重置间隔=1 天，lapse++ |
| 模糊 Hard | 3 | 想起但困难 | 间隔×1.2 |
| 正确 Good | 4 | 正常想起 | 间隔×EaseFactor |
| 轻松 Easy | 5 | 毫不费力 | 间隔×EaseFactor×1.3 |

> 为降低摩擦采用 4 档（去掉 SM-2 的 0/1 档）。内部映射：2/3/4/5。

## 3.5 移动优先体验规范（Mobile-first）

**定位**：Obsidian iOS/Android 是主场景。所有复习与建卡交互必须默认在手机竖屏、单手拇指可操作，且**无硬件键盘也可完整使用**。桌面端仅是超集，不得反向限制移动体验。

### 3.5.1 单手拇指区（Thumb Zone）
- 所有高频控件（评分栏、揭晓按钮、进度、退出）置于**拇指自然弧区**：屏幕底部 1/3 的左右 60% 内。
- 评分栏固定为**底部粘性栏**（非页面滚动内容），4 档按钮横向均匀分布，**始终在拇指可及高度**。
- 顶部仅放低频率控件（退出/设置）。禁止把核心操作放在屏幕顶角。
- 左右手切换：提供"评分栏靠左/靠右"设置（镜像布局），适配左手持机。

### 3.5.2 最小触控尺寸（Tap Target）
- 所有可点元素**最小 44×44pt**（Apple HIG）／**48dp**（Material），评分按钮推荐 **52×56pt**。
- 相邻可点元素间距 ≥ 8pt，防止误触相邻评分。
- 卡片主体（问题/答案）不可整体触发"揭晓"以外的动作，避免手势冲突。

### 3.5.3 安全区（Safe Area）
- 内容与评分栏避开刘海/圆角/Home 指示条：使用 `env(safe-area-inset-*)` 做底部/顶部 padding。
- 评分粘性栏底部 padding 至少 `env(safe-area-inset-bottom) + 8px`，防止 Home 条覆盖按钮。
- 键盘弹出时不遮挡评分栏（见 3.5.7）。

### 3.5.4 动态视口（Dynamic Viewport）
- 用 `100dvh`（dynamic viewport height）而非 `100vh`，避免移动浏览器地址栏收起/弹出导致的跳变。
- 复习界面为**全屏沉浸式**：隐藏 Obsidian 原生 tab/工具栏（进入复习时），退出会话时恢复。
- 横屏（landscape）时评分栏改为**右侧纵向堆叠**（4 档竖直排列），高度自适应；横屏高度有限时不强制横向排布。

### 3.5.5 长答案滚动（Long Answer Scrolling）
- 问题页/答案页内容区为**独立可滚动容器**（`overflow-y: auto`），评分栏保持粘性不动。
- 长答案滚动时给出"已到末尾"提示（如答案底部进度指示或"↓ 滑到底评分"轻提示），避免用户误以为卡住。
- 答案滚动到底后评分栏轻微上浮提示可用（视觉反馈，不阻断）。
- 评分前可回滚重看答案；评分只在用户明确点击时触发，滚动不误触发评分。

### 3.5.6 横竖屏 / 小屏（Orientation & Small Screens）
- 最小支持宽度 320px（iPhone SE 1st 级）。<360px 时评分按钮字号缩小至 14px、间距收紧但仍 ≥ 44pt 可点。
- 横竖屏切换**不丢会话状态**：使用 `onResize` 重新布局，内容区高度重算，不重置当前卡片。
- 小屏限制单屏显示密度：问题文本 ≤ 4 行默认字号，可点放大（zoom）。

### 3.5.7 软键盘（Soft Keyboard）
- 建卡输入框聚焦时 `scrollIntoView` 到键盘上方，且使用 `visualViewport` API 感知键盘高度，避免被遮挡。
- 键盘弹出后评分栏/提交按钮**自动上移**到键盘上方（`bottom: keyboardHeight + safe-area`）。
- 建卡页采用**顶部大标题 + 底部固定"保存/下一步"按钮**模式，输入区居中留白减少键盘跳动。
- 键盘工具栏（KeyboardAccessory/自定义）提供"下一行/插入分隔符/保存"快捷按钮，减少拇指往返。

### 3.5.8 手势与防误触（Gestures & Anti-Mistouch）
- 左滑 = 上张卡、右滑 = 下一张（可选，默认关闭以免与 Obsidian 手势冲突）。
- 关键操作（评分、退出会话）默认**不做**轻扫触发，只用明确点按，防止走路/单手时误操作。
- "退出会话"需二次确认（防误触），并明确告知"未完成卡仍会保留在队列"（不丢进度）。
- 双击 / 长按：仅用于非破坏性辅助（如长按卡片复制），不用于评分。

### 3.5.9 无键盘完整操作（No-Keyboard Parity）
- **无硬件键盘也必须 100% 可操作**：揭晓=点按问题区，评分=点评分按钮。所有功能不依赖快捷键。
- 快捷键（空格揭晓 / 1-4 评分）为**桌面增强**，移动端用等价的触控路径（底部按钮）实现同一动作。
- 无障碍：评分按钮带 `aria-label`（忘记/模糊/正确/轻松）与 `role="button"`；进度条带 `aria-live`；揭晓区为可聚焦 button，支持屏幕阅读器焦点。

### 3.5.10 会话中断 / 恢复（Session Interruption & Resume）
- **会话快照**：每评一张卡即写入会话状态（当前 cardId + 剩余队列）到内存 + 防抖持久化（可复用 §7 debounce 机制）。
- App 切后台 / 来电 / 锁屏 → 自动保存快照；回来时提示"继续上次复习？[继续] [重新开始] [退出]"，**继续**不重放已完成卡。
- 崩溃 / 手动关闭 → 下次打开从快照恢复，未完成卡不丢、已完成卡不重复。
- 会话超时（如中断 > 24h）：不强行结束，仅提示"进度已保存，可稍后继续"。

### 3.5.11 性能（Mobile Performance）
- 目标：冷启动进复习 < 500ms；卡切换 < 100ms；评分→下一张 < 100ms（无卡顿感）。
- 卡片解析缓存 + 惰性渲染（一次只渲染当前卡，虚拟化长队列，不预渲染全部 DOM）。
- 图片/内嵌资源懒加载；data.json 读写防抖（§7），评分高频不阻塞主线程。
- 禁止在复习主流程做同步磁盘 IO / 全量 markdown 重解析。

### 3.5.12 可访问性（Accessibility）
- 对比度 ≥ WCAG 2.1 AA；支持系统"增强对比度 / 大字体 / 减少动态效果"。
- 跟随系统深色模式（复用 §设计系统暗色 token）。
- VoiceOver / TalkBack：评分栏为横向 button 组，评分结果播报（"正确，下一张"）。
- 触控目标、文本缩放、方向锁定设置遵循用户系统偏好，插件不强改。

## 4. 调度算法（间隔重复）

采用 **SM-2 派生 + 每次评分后重算**，纯 TypeScript、无外部依赖、可离线。

### 4.1 参数
- `EaseFactor`（难度系数）初始 2.5，范围 [1.3, 3.0]。
- 最短间隔 1 天；初始学习序列：1 天 → 3 天 → 6 天（三次"新手期"）。

### 4.2 算法（伪代码）
```
复习(card, grade):
  if grade < 3:                    # 忘记
    card.state.reps = 0
    card.state.intervalDays = 1
    card.state.lapses += 1
  else:
    if card.state.reps == 0:        # 首次
      card.state.intervalDays = 1
    elif card.state.reps == 1:
      card.state.intervalDays = 3
    elif card.state.reps == 2:
      card.state.intervalDays = 6
    else:
      factor = grade==5 ? 1.3 : (grade==3 ? 1.2 : 1.0)
      card.state.intervalDays = max(1, round(intervalDays * easeFactor * factor))
    card.state.reps += 1
  # 更新难度
  card.state.easeFactor = clamp(
    easeFactor + (0.1 - (5-grade) * (0.08 + (5-grade) * 0.02)),
    1.3, 3.0
  )
  card.state.dueAt = now + intervalDays 天
```

### 4.3 过期处理
到期日已过 → `dueAt` 不重排，直接进入今日队列（按过期天数升序）。连续多张同一张卡只复习一次。

### 4.4 每日队列构建
1. 所有 `dueAt <= now` 的卡。
2. 按"过期天数 + 上次评分（低分优先）"排序。
3. 上限：用户设置 `dailyLimit`（默认 20）；超出的顺延次日。

### 4.5 新卡引入
每日新卡上限 `newPerDay`（默认 10），与新复习卡混合（每 5 张复习插 1 张新卡），避免一次性堆积导致"刷量"。

## 5. 统计指标（仪表盘）

持久化每次复习事件（`reviewLog`，可关）。

**核心指标**
- 今日到期数 / 已完成数 / 剩余数。
- 连续打卡天数（streak）。
- 掌握度：各卡片最近评分；"成熟卡"（间隔≥21 天）占比。
- 每卡难度趋势（EaseFactor 变化曲线）。

**数据质量指标（反作弊相关）**
- 平均揭晓前思考时长（meditationTime）。
- "揭晓即评分"比例（<2 秒 → 疑似不看题）。
- 评分分布（若 >80% 为"正确/轻松"→ 疑似刷量，提示）。
- 预测正确率 vs 实际评分偏差。

## 6. 低摩擦 / 行为设计（Behavioral Nudge Engine）

- **默认进入**：打开复习命令即开始，无前置配置阻塞。
- **微激励**：每完成 5 张，"🔥 连对 3 张！再来一组？"（变量奖励，非固定表扬）。
- **温和 off-ramp**：会话结束"完成 15 张，很棒！今天到此为止，还是再来 5 分钟？"——避免疲惫导致的低质量评分。
- **认知负荷控制**：永不显示"50 张待复习"的压迫式列表；只显示"今天 X 张，建议 5 分钟"。
- **缺口提醒**：仅一条可行动提示（"你有 8 张卡该复习了"），不轰炸。

## 7. 持久化与数据流

```
Obsidian 笔记（.md）
   ↓ 解析 (markdown parser)
卡片索引（内存 + cache）
   ↓
复习状态 data.json
   ↓ 调度器
今日队列 → 复习会话 → 评分 → 更新 data.json + reviewLog
   ↓
统计仪表盘（读 data.json + reviewLog）
```

- 笔记文件是**唯一事实源**（卡片内容）；data.json 只存进度（可由笔记重建，防损坏）。
- 写入节流：评分后 debounce 300ms 写盘，避免性能抖动。

## 8. 反作弊 / 防熟悉感偏差（关键设计）

熟悉感偏差 = 用户看到问题"眼熟"，未真正回忆就揭晓并评高分 → 数据虚高、实际未掌握。

### 8.1 检测机制（运行时）
- **揭晓过快**：揭晓前思考时间 < 3 秒 → 提示"先试着回忆"。
- **评分过快**：揭晓到评分 < 2 秒 → 提示并默认降档（除非强制确认）。
- **评分分布异常**：滚动窗口内 `(Good+Easy) > 85%` 且揭晓时长普遍 < 3s → 判定为"刷量"，弹出诚实提醒："看起来评分偏高，请按真实回忆程度评分。"

### 8.2 主动回忆强制（结构性防偏差）
- 默认**无"立即揭晓"预览**：问题页不显示任何答案线索。
- 提供 `memtype: 多选/填空` 变体（v0.2）：让用户先输入/选择，系统校验后再揭晓——从机制上杜绝"眼熟即对"。
- 评分按钮文案为行为导向（"我真的记住了吗？"），而非印象导向（"这个我见过"）。

### 8.3 数据校正
- 低可信评分（揭晓<3s + 高 Easy 率）的卡片，在下次调度时**强制缩短间隔 50%**，促使真实复习。
- reviewLog 标记可疑事件 `flag: "too_fast"`，供统计呈现。

### 8.4 信任优先原则
防作弊不是为了惩罚用户，而是保护**真实学习效果**。所有提示使用鼓励性语言（"为了帮你记得更牢"），不用指责措辞。

## 10. 实现分层与验收（供实现成员）

### 10.1 模块划分
1. **Parser**：md → 卡片列表（frontmatter + 分隔符）。
2. **Scheduler**：SM-2 派生调度（纯函数，易单测）。
3. **Store**：data.json 读写 + debounce。
4. **Review UI**：问题/答案视图、评分栏、进度条。
5. **Stats**：仪表盘 + reviewLog。
6. **AntiCheat**：§8 检测逻辑（纯函数，易单测）。

### 10.2 验收清单
- [ ] 从文件夹递归读取卡片并正确解析问题/答案/注解。
- [ ] 手动创建卡片可写入笔记并立即进入索引。
- [ ] 复习会话：问题→揭晓→评分→下一张，全程≤2 次点击。
- [ ] 调度器单测：给定 grade 序列，间隔/EaseFactor/到期时间符合 §4。
- [ ] 重启插件后进度不丢失（data.json 恢复）。
- [ ] 防作弊：模拟快速揭晓+高 Easy → 触发提示与间隔缩短。
- [ ] 统计页正确显示到期/完成/掌握率/连续打卡。
- [ ] 键盘全程可操作（空格/1-4）。

**移动优先验收（§3.5）**
- [ ] 竖屏单手：评分栏为底部粘性栏，全部核心控件在拇指弧区。
- [ ] 所有可点元素触控尺寸 ≥ 44×44pt，相邻间距 ≥ 8pt。
- [ ] 刘海/Home 条：评分栏使用 safe-area-inset 避让，键盘弹出不上盖按钮。
- [ ] 用 `100dvh` 渲染，无地址栏收起跳变；横屏时评分栏切换为右侧纵向堆叠且不丢会话。
- [ ] 长答案独立滚动，评分栏保持粘性；滚动到底给出"可评分"提示。
- [ ] 最小 320px 可用；小屏评分按钮可点且不被压缩失真。
- [ ] 建卡：软键盘不遮挡输入框，保存按钮自动上移到键盘上方，提供键盘工具栏快捷按钮。
- [ ] 无硬件键盘可 100% 完成 揭晓+评分 全部操作；快捷键仅为桌面增强。
- [ ] 退出会话需二次确认，且告知"未完成卡会保留"。
- [ ] 会话中断/切后台/崩溃后可从快照恢复，已完成卡不重复、未完成卡不丢。
- [ ] 性能：卡切换 < 100ms、评分→下一张 < 100ms；惰性渲染、无主线程阻塞 IO。
- [ ] 无障碍：评分按钮带 aria-label/role、进度条 aria-live、VoiceOver/TalkBack 可播报评分结果；对比度 AA、跟随系统深色。

### 10.3 测试策略
- 调度器 + 解析器 + 防作弊 = 纯函数 → Jest/Vitest 单元测试。
- UI 流 → Obsidian 沙箱手测 + 最小 e2e。

## 11. 与并行任务的关系
- 与"调研现有插件"任务（Hermes）对齐：本规格的调度算法、卡片格式为**自研基线**；若调研发现可借用的成熟算法/格式，仅替换 §4 的调度核心，接口（§2/§3）不变。
- 与"实现基础版本"任务（Grok Build）对齐：本规格 §1-§4、§10 即为可实现需求；实现以"先跑通再完善"为准。
